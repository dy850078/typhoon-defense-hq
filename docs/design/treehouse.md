# 小樹屋設計文件

> 狀態：已上線（PR #57、#60、#62、#64）。最後更新：2026-10-26

## 1. 目標

讓總部裡的人可以分成小群組，直接用語音（和視訊、分享螢幕）聊天。

- 同一間小樹屋的人互相聽得到，走到地圖哪裡都一樣。地圖上不用真的有一間屋子。
- 有一個介面列出現在有哪些小樹屋、裡面有誰（大頭貼、名字、帳號、職業、等級）。
- 規模：整個總部大約 20 人同時在線，一間最多 8 人。

**不做的事：** 錄音、文字聊天室（遊戲本來就有聊天）、跟陌生人配對、超過 8 人的大會議（大會議用戰情室的 Jitsi）。

## 2. 為什麼選遊戲內 WebRTC

| 方案 | 優點 | 缺點 |
| --- | --- | --- |
| **遊戲內 WebRTC（採用）** | 不用離開遊戲；可以做講話光圈、名牌麥克風、個別音量；聲音不經過我們的伺服器 | 要自己處理連線、NAT 穿透 |
| 每間開一個 Jitsi 分頁 | 不用寫連線邏輯 | 要切分頁、沒辦法跟遊戲畫面整合；meet.jit.si 嵌入 5 分鐘會被切 |

2026-10-25 ZS 選遊戲內 WebRTC。視訊也一樣選遊戲內。

## 3. 整體架構

```
玩家瀏覽器 A ──┐                         ┌── 玩家瀏覽器 B
               │  Socket.IO（誰在哪間、   │
               ├─ 轉送連線資訊 rtc）──────┤
               │      node server.js      │
               │                          │
               └──── WebRTC 直連 ─────────┘   （聲音／畫面不經過 server）
                       │ 直連不通時
                       └── Cloudflare TURN 中繼
```

- **伺服器只做三件事：** 記住誰在哪間（狀態）、在同屋的人之間轉送 WebRTC 連線資訊、發中繼通行證並統計中繼用量。
- **聲音和畫面不經過伺服器。** 同屋的人兩兩各連一條（full mesh）。8 人一間時，每個人有 7 條連線。

## 4. 伺服器（server.js）

### 狀態

```js
trees: Map<id, { id, name, owner, ownerName, at, members: [socket id] }>
player.tree       // 在哪間（null = 沒在屋裡）
player.treeMuted  // 自己靜音
player.treeVideo  // '' | 'cam' | 'screen'
```

- `TREE_CAP = 8`（一間最多人數），`TREE_MAX = 12`（最多幾間）。
- 狀態只放在記憶體。伺服器重開之後小樹屋全部消失，大家重新進就好。

### 事件

| 事件 | 方向 | 說明 |
| --- | --- | --- |
| `treeList` | client→server（ack） | 拿目前列表 |
| `treeCreate {name}` | client→server（ack） | 蓋一間並住進去；回 `{ok, id, peers: [], ice}` |
| `treeJoin id` | client→server（ack） | 進別人的；回 `{ok, id, peers: [屋裡其他人], ice}` |
| `treeLeave` | client→server | 離開 |
| `treeMute bool` | client→server | 靜音狀態（大家都看得到） |
| `treeVideo 'cam'/'screen'/''` | client→server | 視訊狀態，讓同屋的人知道要不要顯示畫面 |
| `rtc {to, data}` | 雙向轉送 | offer / answer / ice。**只轉給同一間的人** |
| `turnUsage bytes` | client→server | 回報這 30 秒走中繼的流量 |
| `trees` | server→all | 任何變動都廣播完整列表 |

- 換屋、斷線、離開總部都會走 `leaveTree(p)`。屋主離開就交給下一個人；沒人了就拆掉。
- `treeCreate` 和 `treeJoin` 會**先**拿好中繼通行證，**再**改狀態。因為拿通行證要等網路，等的時候玩家可能已經離開。

## 5. 瀏覽器（public/game.js 的 `TREE` 模組）

### 連線流程

1. 按「蓋一間」或「進去」時，**當下**要麥克風權限（手機只有在使用者按下去的那一刻才准）。
2. 伺服器回傳屋裡其他人，由**新進來的人**對每個人送 offer，原本在屋裡的人只負責回 answer。這樣不會兩邊同時打給對方。
3. 每個對象一條 promise 隊伍，依序處理 sdp / ice。ice 可能比 offer 先處理完，排隊可以避免順序錯亂。
4. 已經連過的人又送 offer 來，代表對方在重連：丟掉舊連線，重新接。

### 連不上的處理

- 每個人旁邊有狀態標籤：連線中… / 已接通 / 連不上。
- 連線 `failed`，或 15 秒還沒接通（有些網路連「失敗」都不會回報），就**自動重連一次**。由 socket id 比較小的那邊重打，避免兩邊同時打。
- 還是不行才跳提示「可能是網路環境擋住了」。

### 麥克風

- 第一次用回音消除、降噪、自動增益。打不開（例如藍牙耳機正在切換成通話模式）就等 0.5 秒，用最基本的設定再試一次。
- 錯誤訊息照真正原因說：沒權限 / 找不到麥克風 / 被別的程式占用。
- 6 秒還沒打開，提醒去看網址列的權限詢問。

### 聲音和音量

- 每個人的聲音接 WebAudio：`MediaStreamSource → GainNode → 喇叭`，所以音量可以調到 200%。`<audio>` 元素設成靜音，只負責讓瀏覽器收音。
- 整體音量一條，每個人各一條（0～200%）。記在這台電腦的 localStorage（`hq-tree-master`、`hq-tree-vols`）。有登入的人用帳號記，沒登入的用名字記。
- 講話偵測：每 150ms 用 AnalyserNode 算音量，超過門檻就算在講話。

### 視訊、分享螢幕

- **每條連線一開始就留好一個視訊位置**（offer 那邊 `addTransceiver('video')`，answer 那邊收到 offer 後把方向設成 sendrecv）。
- 開關攝影機、換成分享螢幕，都只是 `replaceTrack` 換畫面，**不用重新談連線**，不會打斷語音，也不會多出新的連線狀態要處理。
- 一次只送一個畫面：攝影機或螢幕，二選一。
- 畫質上限：

  | 畫面 | 解析度 | 每秒張數 | 頻寬上限 |
  | --- | --- | --- | --- |
  | 攝影機 | 320×240 | 15 | 250 kbps |
  | 分享螢幕 | 原尺寸 | 8 | 900 kbps |

- 分享螢幕只有電腦版瀏覽器有（手機瀏覽器不支援 `getDisplayMedia`），沒有就不顯示按鈕。
- 要不要顯示某人的畫面，看伺服器廣播的 `member.video`，而不是看收到的畫面本身（遠端關掉時畫面可能停在最後一格）。

### 介面

- **工具列：** 「小樹屋」按鈕；在屋裡時多三顆：麥克風、攝影機、分享螢幕（共用 class `.tree-tool`，工具包收起時仍然顯示）。
- **小樹屋卡片：** 每間顯示名稱、屋主、蓋了多久、人數；成員顯示大頭貼、名字、帳號、職業、等級，以及靜音、視訊圖示。同屋的人還會顯示連線狀態和個別音量條。
- **名牌：** 在屋裡的人名牌旁有麥克風圖示，靜音時是斜線麥克風（大家都看得到）；講話時有綠色音波往外擴（只有同屋的人看得到）。
- **視訊小窗：** 有人開畫面才出現。電腦在右上、手機在左上；可拖動（位置記在 `hq-tree-vpos`）、可收起；點一下畫面放大，再點縮回。
- **大畫面：** 小窗標題列的「大畫面」把同一個小窗撐滿畫面，同屋**每個人**都排進來，沒開視訊的人顯示頭像，講話的有綠框。沒人分享螢幕時排成接近正方形的格子（直的手機畫面最多兩欄）；有人分享螢幕時螢幕占主畫面，其他人排在旁邊（直的畫面排在下面）。按「✕ 縮小」或 Esc 回到小窗；所有人都關掉畫面時自動收起。
- **鏡頭預設關閉：** 進小樹屋只開麥克風，視訊要自己按。
- 所有圖示都是手繪蠟筆風（public/icons.js），不用系統 emoji。

## 6. NAT 穿透和中繼

### 問題

手機 4G/5G、公司、學校網路常常不讓外面直接連進來。兩個人都在這種網路時，只靠 STUN 連不上，兩邊都會聽不到對方（ZS 跟 hank 就是這樣）。

### 做法

- 預設用 Google STUN。
- 設了 `CF_TURN_KEY_ID` / `CF_TURN_KEY_TOKEN` 就用 Cloudflare Realtime TURN。伺服器跟 Cloudflare 要通行證，進屋時放在 ack 的 `ice` 裡發給玩家。
- 會過濾掉 `:53` 的網址，因為瀏覽器會擋 53 port，留著只會讓連線多等一段逾時。
- 也支援 Metered（`TURN_API_URL`），或自架 TURN（`TURN_URL` / `TURN_USER` / `TURN_PASS`）。
- **只有直連不通的那幾對會走中繼，**其他人照樣直連。
- 中繼看不到內容：WebRTC 的聲音和畫面是端對端加密的。

### 通行證有效期

- Cloudflare 通行證 **6 小時**過期（2026-10-26 ZS 決定，原本是 24 小時）。
- 同一張通行證最多發 1 小時就換新的，所以拿到的人至少還能用 5 小時。
- **取捨：** 越短，到上限後中繼停得越快；但走中繼、連續講超過有效期的那對會斷線，要重進小樹屋。1 小時太容易斷，24 小時停得太慢，所以取 6 小時。

## 7. 中繼用量上限

Cloudflare 每月免費 1000GB，超過要付錢，而且 Cloudflare **沒有硬性的花費上限**，只有帳單提醒。所以我們自己加了一層上限：

- 每 30 秒，瀏覽器用 `getStats()` 找出目前使用中的連線路徑，如果有一端是 relay，就把這段時間的流量回報給伺服器（`turnUsage`）。單次最多算 50MB，避免亂報。
- 伺服器累加，存在 `data/turn-usage.json`，每個月（UTC 月份）重算，最多每分鐘存一次檔。
- 到上限 `TURN_LIMIT_GB`（預設 800GB）就不再發中繼通行證，只剩直連。
- 管理員頁面顯示這個月的用量。

### 它不是嚴謹的保證

| 漏洞 | 影響 |
| --- | --- |
| 用量是瀏覽器自己報的 | 改過的網頁可以少報或不報 |
| 到上限只是停發新通行證 | 已發出的最多再用 6 小時 |
| 通行證可以從瀏覽器拿出來 | 被拿去別處用的流量完全不會算到 |
| 關分頁前最後不到 30 秒沒報；伺服器當掉少記最多 1 分鐘 | 小誤差；兩端各報一次，整體是多算的 |

**真正的硬保險是 Cloudflare 的帳單提醒（建議設 $1）**，只有它看得到真實用量。

### 流量估算（只算走中繼的那幾對）

| 內容 | 一小時約 |
| --- | --- |
| 語音 | 36 MB |
| 視訊 | 再多 100 MB |
| 分享螢幕 | 再多 400 MB |

20 人左右的聚會，正常用法離上限很遠。例如 3 對人走中繼、每天視訊 2 小時，一個月大約 60GB。

## 8. 已知限制

- **Full mesh：** 8 人一間開視訊時，每個人要上傳 7 份畫面（約 1.75 Mbps），網路差的人會吃力。要更多人就得改成 SFU（例如 Cloudflare Calls、LiveKit），這不在目前範圍。
- 伺服器重開，小樹屋會全部消失。
- 視訊小窗的位置只記在這台電腦。

## 9. 怎麼測

- Playwright 開多個分頁，用 `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream` 產生假麥克風和攝影機。
- 用 `--use-file-for-fake-audio-capture=silent.wav` 讓假麥克風安靜，不然會一直被判斷成在講話。
- 分享螢幕：在頁面裡把 `getDisplayMedia` 換成一張畫布的 `captureStream()`。
- 等 HUD 出現要用 `waitForFunction(() => !document.getElementById('hud').hidden)`，因為 `#hud` 本身沒有大小，`waitForSelector` 會判斷成看不到。
- 測中繼：本機跑一個 TURN（例如 node-turn），把 ICE 限制成只走 relay，確認可以接通，管理員頁的用量也會往上加。

| 環境變數 | 說明 |
| --- | --- |
| `CF_TURN_KEY_ID` / `CF_TURN_KEY_TOKEN` | Cloudflare TURN 金鑰（不要貼到聊天或 commit 進 repo） |
| `TURN_LIMIT_GB` | 每月中繼上限，預設 800 |
| `TURN_API_URL` | Metered 的通行證網址 |
| `TURN_URL` / `TURN_USER` / `TURN_PASS` | 自架 TURN |
